# Как участвовать

Спасибо, что хотите помочь. Больше всего проекту нужны две вещи: новые русские приметы с примерами и отчёты о ложных срабатываниях.

## Сообщить о ложном срабатывании

Откройте задачу по шаблону «Ложное срабатывание». Приложите фрагмент текста (без персональных данных), команду, которой запускали детектор, и объясните, почему находка неверна. Ложные срабатывания на живом научном и деловом тексте — главный риск проекта, поэтому такие задачи разбираются первыми.

## Предложить новую примету

Шаблон «Новая примета». Хорошее предложение содержит:

- два-три примера из реальных текстов моделей (с указанием модели, если известна);
- пример, где та же конструкция законна, и как их различить;
- замену: конкретный вариант, а не «перефразировать»;
- уровень: 1А (маркер ИИ), 1Б (канцелярит, не довод об авторстве), 2 (в скоплении), 3 (по плотности), или отдельная категория каталога.

## Как устроены изменения

- Правила для агента живут в `skills/avoid-ai-writing-russian/SKILL.md` и `references/patterns.md`. Детектор (`src/`) исполняет ту часть правил, которую можно поймать регулярными выражениями и статистикой.
- Добавляя запись в `src/lexicon.ts`, добавьте её и в каталог `patterns.md`, и тест в `test/`. Проверьте, что новое правило не срабатывает на `test/fixtures/corpus/human/`.
- Каждый тип находки должен иметь вес в `WEIGHTS` и подпись в `TYPE_LABELS` (`src/detect.ts`); это проверяет `test/lexicon.test.ts`.
- В исходниках не должно быть невидимых символов: пишите их через `\u200B`-экранирование. Это тоже проверяется тестом.
- Правила, которые требуют понимания смысла, оставляйте только в каталоге и помечайте, что детектор их не ищет. Точность важнее полноты.

## Хуки

Проект использует [prek](https://prek.j178.dev), быструю замену pre-commit. После клонирования:

```bash
prek install --hook-type pre-commit --hook-type commit-msg --hook-type pre-push
```

Перед коммитом проверяются гигиена файлов, секреты (gitleaks), формат и линтер (Biome), типы, невидимые символы, синхронность версий и документация собственным детектором. Сообщение коммита должно быть на русском, до 72 знаков в первой строке, без точки в конце. Перед отправкой запускаются тесты. Прогнать всё вручную: `prek run --all-files`.

## Выпуск версии

1. Записи копятся в разделе «Не выпущено» в `CHANGELOG.md`.
2. `bun run release patch` (или `minor`, `major`, `X.Y.Z`; `--dry-run` покажет план). Скрипт проверит ветку и чистоту дерева, прогонит типы и тесты, перенесёт «Не выпущено» в раздел версии, обновит версию во всех манифестах, скиллах и `CITATION.cff`, сделает коммит «Выпуск X.Y.Z» и тег `vX.Y.Z`.
3. `git push --follow-tags`. По тегу GitHub Actions ещё раз прогонит проверки, соберёт бинарники `aiw-ru` под Linux, macOS и Windows, архив скиллов и контрольные суммы и опубликует выпуск с заметками из CHANGELOG.

## Поведенческие проверки скилла

`bun run eval` отправляет случаи из `evals/cases.json` живому агенту (по умолчанию `claude -p`) и оценивает ответы: сохранились ли цитаты и числа, не выдуманы ли факты, не осталось ли штампов. В CI не запускается, потому что стоит денег и зависит от модели. Меняя правила скилла, прогоните хотя бы затронутые случаи: `bun run eval --case vak-protected`.
