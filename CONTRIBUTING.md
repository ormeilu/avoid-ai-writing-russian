# Как участвовать

Спасибо, что хотите помочь. Больше всего проекту нужны две вещи: новые русские приметы с примерами и отчёты о ложных срабатываниях.

## Сообщить о ложном срабатывании

Откройте задачу по шаблону «Ложное срабатывание». Приложите фрагмент текста (без персональных данных), команду, которой запускали детектор, и объясните, почему находка неверна. Ложные срабатывания на живом научном и деловом тексте — главный риск проекта, поэтому такие задачи разбираются первыми.

## Предложить новую примету

Шаблон «Новая примета». Хорошее предложение содержит:

- два-три примера из реальных текстов моделей (с указанием модели, если известна);
- пример, где та же конструкция законна, и как их различить;
- замену: конкретный вариант, а не «перефразировать»;
- уровень: 1А (маркер ИИ), 1Б (канцелярит, не довод об авторстве), 2 (в скоплении), 3 (по плотности), или отдельная категория каталога.

## Как устроены изменения

- Правила для агента живут в `skills/avoid-ai-writing-russian/SKILL.md` и `references/patterns.md`. Детектор (пакет `src/aiw_ru/`) исполняет ту часть правил, которую можно поймать регулярными выражениями и статистикой.
- Добавляя запись в `src/aiw_ru/lexicon.py`, добавьте её и в каталог `patterns.md`, и тест в `tests/`. Проверьте, что новое правило не срабатывает на `tests/fixtures/corpus/human/`.
- Каждый тип находки должен иметь вес в `WEIGHTS` и подпись в `TYPE_LABELS` (`src/aiw_ru/detect.py`); это проверяет `tests/test_lexicon.py`.
- В исходниках не должно быть невидимых символов: пишите их через экранирование `\u200b` или `chr()`. Это тоже проверяется тестом.
- Правила, которые требуют понимания смысла, оставляйте только в каталоге и помечайте, что детектор их не ищет. Точность важнее полноты.

## Проверки перед запросом на слияние

Окружение для разработки ставит [uv](https://docs.astral.sh/uv/). По умолчанию группы зависимостей не ставятся, чтобы скилл у пользователя получал только детектор, поэтому для разработки нужны все группы:

```bash
uv sync --group dev --group train
```

```bash
uv run pytest
```

```bash
uv run ty check
```

```bash
uv run prek run --all-files
```

Последняя команда прогоняет все хуки: ruff, ty, невидимые символы, синхронность версий и самопроверку документации.

Документация проекта сама проходит через детектор: если `selfscan` нашёл примету в вашем тексте, перепишите его.

## Хуки

Проект использует [prek](https://prek.j178.dev), быструю замену pre-commit. После клонирования:

```bash
uv run prek install --hook-type pre-commit --hook-type commit-msg --hook-type pre-push
```

Перед коммитом проверяются гигиена файлов, секреты (gitleaks), формат и линтер (ruff), типы (ty), невидимые символы, синхронность версий и документация собственным детектором. Сообщение коммита должно быть на русском, до 72 знаков в первой строке, без точки в конце. Перед отправкой запускаются тесты.

## Выпуск версии

1. Записи копятся в разделе «Не выпущено» в `CHANGELOG.md`.
2. `uv run python scripts/release.py patch` (или `minor`, `major`, `X.Y.Z`; `--dry-run` покажет план). Скрипт проверит ветку и чистоту дерева, прогонит типы и тесты, перенесёт «Не выпущено» в раздел версии, обновит версию в `pyproject.toml`, манифестах, скиллах и `CITATION.cff`, обновит `uv.lock`, сделает коммит «Выпуск X.Y.Z» и тег `vX.Y.Z`.
3. `git push --follow-tags`. По тегу GitHub Actions ещё раз прогонит проверки, соберёт пакет, опубликует его на PyPI и создаст выпуск на GitHub с архивом скиллов, контрольными суммами и заметками из CHANGELOG. На PyPI пакет уходит через доверенную публикацию: PyPI проверяет токен OIDC от workflow `release.yml` в окружении `pypi`, паролей и API-токенов в секретах нет.

## Поведенческие проверки скилла

`uv run python evals/run.py` отправляет случаи из `evals/cases.json` живому агенту (по умолчанию `claude -p`) и оценивает ответы: сохранились ли цитаты и числа, не выдуманы ли факты, не осталось ли штампов. В CI не запускается, потому что стоит денег и зависит от модели. Меняя правила скилла, прогоните хотя бы затронутые случаи: `uv run python evals/run.py --case vak-protected`.

## Замеры на корпусах

Скрипты замеров и обучения лежат в `scripts/` и в плагин не входят. Их зависимости (LightGBM, scikit-learn, numpy, huggingface-hub) лежат в группе `train`, инструменты разработки — в группе `dev`. Детектор скрипты зовут прямо из пакета `aiw_ru` в нескольких процессах. Данные хранятся вне репозитория, в `~/.cache/aiw-ru/llmtrace` (путь меняет `AIW_RU_DATA`): тестовая часть LLMTrace весит сотни мегабайт, а человеческие тексты корпуса пришли из сторонних источников со своими лицензиями.

```bash
uv run --group train scripts/llmtrace.py fetch --set classification --split test
```

```bash
uv run --group train scripts/llmtrace.py eval --limit 5000
```

`eval` считает оценку детектора классификатором (ROC AUC, accuracy, F1 при разных порогах) и показывает для каждого правила, как часто оно срабатывает у людей и у моделей. Добавляя или меняя правило, посмотрите на его строку: если у людей оно срабатывает не реже, чем у моделей, правило вредит оценке. Примеры срабатываний на людях выводит `--rule ТИП`. `spans` сверяет фрагменты `antiplagiat` с разметкой ИИ-кусков в наборе `detection`. Ответы детектора кэшируются рядом с данными по хэшу исходников `src/aiw_ru/`: после правки правила повторный прогон пересчитает их сам.

## Модель LightGBM

```bash
uv run --group train scripts/train.py
```

Скрипт обучает LightGBM отличать тексты людей от текстов моделей: учится на train-части LLMTrace, число деревьев подбирает по valid, проверяется на test. Все три части сначала скачивает `llmtrace.py fetch`. Признаки считает `aiw_ru.features`, тот же модуль, которым пользуется `aiw-ru`, когда проверяет текст моделью.

Модель, описание признаков, метрики и карточка пишутся в `~/.cache/aiw-ru/llmtrace/lightgbm/`. После полного обучения папка уходит в [toiletsandpaper/russian-ai-text-detector-lightgbm](https://huggingface.co/toiletsandpaper/russian-ai-text-detector-lightgbm) на Hugging Face, в коллекцию `aiw-ru`. Нужен `hf auth login` с правом записи в репозиторий; `--no-push` оставляет модель локальной, `--limit N` тоже. Карточку собирает `scripts/hub.py` из `metrics.json`: метаданные `model-index` с результатами на LLMTrace и таблицы по жанрам, длине текста, типу задания и модели-генератору.

Меняя состав или порядок признаков, поднимите `FEATURES_VERSION` в `src/aiw_ru/features.py`. Модель старой версии тогда откажется работать с новым кодом, пока её не переобучат. Проверить только что обученную модель до выкладки можно так: `AIW_RU_MODEL_DIR=~/.cache/aiw-ru/llmtrace/lightgbm uv run aiw-ru classify текст.md`.
