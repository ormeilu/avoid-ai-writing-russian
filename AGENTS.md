# AGENTS.md

Инструкции для ИИ-агентов, которые работают с этим репозиторием.

## Что это

Русская адаптация скилла [avoid-ai-writing](https://github.com/conorbronsdon/avoid-ai-writing): два скилла (`skills/avoid-ai-writing-russian`, `skills/antiplagiat`) и детектор на Python (пакет `aiw_ru` в `src/`, команда `aiw-ru`). Всё пишется на русском: документация, комментарии, сообщения коммитов. Идентификаторы в коде — на английском.

## Устройство

- `skills/avoid-ai-writing-russian/SKILL.md` — точка входа скилла: договор о правке, режимы, уровни серьёзности, формат ответа, «никогда не добавляй». Держать короче 500 строк.
- `skills/avoid-ai-writing-russian/references/` — каталог примет по темам (`vocabulary.md`, `typography.md`, `sentences.md`, `rhetoric.md`, `chat.md`, `structure.md`) и профили контекста и голоса (`profiles.md`), а ещё справки о моделях (`models.md`), слепом судье (`judge.md`) и проверке правки свежим агентом (`review.md`). Оглавление и порядок чтения в SKILL.md: агент открывает файл темы, когда правит находку из неё, а не весь каталог.
- `skills/antiplagiat/SKILL.md` — под-скилл подготовки к «Антиплагиату» и «Думейту»; `skills/antiplagiat/references/domate.md` — отчёт «Думейта», тепловая карта и скрипт для страницы отчёта; `skills/antiplagiat/references/antiplagiat.md` — уровни признаков ИИ в отчёте «Антиплагиата», версия модели и ручное исключение фрагментов.
- `src/aiw_ru/text.py` — нормализация (невидимые символы, подмена букв, ё→е) с картой смещений, маскирование защищённых областей, разбиение на блоки и предложения.
- `src/aiw_ru/lexicon.py` — словари примет на мини-языке фраз (`*` — любое окончание).
- `src/aiw_ru/detect.py` — детектор: словари, отпечатки, типографика, структура, стилометрия, оценка.
- `src/aiw_ru/antiplagiat.py` — оценка по фрагментам, разметка из отчёта (куски и тепловая карта) и калибровка по системам (`--system`).
- `src/aiw_ru/calibration.py` — импорт отчётов в калибровку: отпечатки документа и разметки, пропуск повторного отчёта, замена по `--replace`, проверка переноса на отложенные документы, атомарная запись с проверкой чужой записи.
- `src/aiw_ru/judge.py` — слепой судья: задание для свежего агента и сводка его ответов; справка в `references/judge.md` основного скилла.
- `src/aiw_ru/validate.py` — проверка сохранности правки.
- `src/aiw_ru/types.py` — результаты для JSON (модели pydantic: поля в snake_case, в JSON — camelCase).
- `src/aiw_ru/compat.py` — семантика JavaScript, с которой переносился детектор: регулярные выражения, округление, trim.
- `src/aiw_ru/features.py` — признаки для LightGBM; `src/aiw_ru/models.py` — необязательные модели с Hugging Face (три трансформера в ONNX и LightGBM), нарезка текста на фрагменты и определение языка.
- `src/aiw_ru/cli.py` — команда `aiw-ru` (вывод через rich), около 2200 строк: целиком не читай, сначала `grep -n '^def cmd_' src/aiw_ru/cli.py`. Каждая команда — одна функция `cmd_<имя>`, таблица команд в `main()` в конце файла.
  - Вверху докстринг с краткой сводкой команд и `USAGE_COMMANDS` (раздел справки о командах, около строки 70). Ниже таблица параметров `OPTIONS` (около строки 130): из неё собирается раздел «Параметры» справки (`render_options`) и проверяется вызов (`check_options`: параметр чужой команды, повтор значения, пары из `CONFLICTS`). Новый параметр добавляй в таблицу и в `parse()` (около строки 330). Между ними и `cmd_*` лежат классы и функции вывода.
- `scripts/check_package.py` — собранный wheel ставится в одноразовое окружение и запускается из пустой папки: `scan`, `validate`, все файлы скиллов, без ML-пакетов и без модулей рабочей копии. Его зовёт CI после `uv build`, в том числе на wheel из sdist. Тесты с группой `transformer` идут отдельным workflow `transformer.yml`.
- `scripts/probability_check.py` — Brier, log loss, надёжность по диапазонам и доли ошибок у порога для вероятностей на размеченных данных; сам скрипт только считает, данные для замера выбирает владелец корпуса.
- `scripts/llmtrace.py`, `scripts/train.py`, `scripts/hub.py` — замер детектора на корпусе LLMTrace, обучение LightGBM и выкладка модели с карточкой на Hugging Face. Подробности в CONTRIBUTING.md, разделы «Замеры на корпусах» и «Модель LightGBM».
- `scripts/release.py` и соседние — выпуск версий, проверки версий, коммитов и невидимых символов; `evals/` — поведенческие проверки скиллов.

## Правила

- Любое правило детектора должно быть описано в каталоге `references/`. Обратное не обязательно: правила на суждение живут только в каталоге.
- Новый тип находки получает вес в `WEIGHTS`, подпись в `TYPE_LABELS` и тест.
- Правило не должно срабатывать на `tests/fixtures/corpus/human/` и `tests/fixtures/corpus/human-regression/`; точность важнее полноты. Известное ложное срабатывание в `human-regression` отмечено в `tests/test_regression_corpus.py` как `xfail(strict=True)` с причиной: правило ради примера не подкручивай, а поправил его — сними отметку.
- Не писать невидимые символы в исходники буквально: только `\uXXXX` или `chr()`.
- Примеры в каталоге, тестах и `evals/` выдуманные, на постороннюю тему: тексты пользователя (статьи, рефераты, диссертации, отчёты проверок) не попадают в репозиторий ни целиком, ни фрагментами. Хук `private-texts` сверяет файлы с работами из `~/.config/aiw-ru/private`.
- Скилл помогает автору с его собственным текстом и с оформлением заимствований как цитирований. Не добавлять приёмы, которые маскируют чужой текст или обманывают проверку техническими уловками.
- Всё, что взято извне (идея, приём, код, веса, данные, замер), в том же изменении попадает в благодарности: `NOTICE.md` (раздел «Данные и источники» или «Идеи из других проектов»: авторы, ссылка, лицензия, что взято и что написано заново), раздел «Благодарности» в README и `references` в `CITATION.cff`. Если источник касается модели или датасета, обнови и карточки на Hugging Face: LightGBM в `scripts/hub.py`, трансформеры в `scripts/train_transformer.py`. Лицензию проверяй до переноса кода и весов.
- Документация проекта должна проходить самопроверку детектором без находок P0 и P1. Хук `selfscan` (`--min P1 --fail-above 30`) останавливает только оценку выше 30 и не смотрит `docs/*.md`, поэтому правленый файл проверь сам: `uv run aiw-ru scan --context docs --min P1 файл`.
- Только абсолютные импорты: `from aiw_ru.text import words`. Относительные запрещены правилом ruff TID252.
- Замеры и обучение живут только в `scripts/`, не в `skills/`; их зависимости в группе `train` (дообучение трансформера — в группе `transformer`), инструменты разработки — в группе `dev`. По умолчанию группы не ставятся: `uv run --project ../..` из скилла получает только детектор. Для разработки `uv sync --group dev --group train`. Корпуса, кэши и обученные модели хранятся вне репозитория (`~/.cache/aiw-ru`, модели — на Hugging Face), в git их не класть.
- Модели необязательны: скиллы и детектор работают без них, а ставить модель агент предлагает пользователю и ставит только с его согласия.
