# Длинные документы

`transformer` и `mini-frida` читают одно окно в 512 токенов, это 300–350 слов. `modernbert` с версии 2.2.0 читает текст целиком до 8192 токенов, это 4–5 тысяч слов. Длинный текст `aiw-ru classify` у всех трёх проверяет по фрагментам в 512 токенов: режет его на куски по границам предложений, соседние куски заходят друг на друга на четверть фрагмента, и у каждого своя вероятность. Здесь замер двух вещей: находят ли фрагменты ИИ-текст, который занимает только часть документа, и как часто они поднимают ложную тревогу на тексте, который целиком написал человек. Отдельно разобрано, почему фрагменты у `modernbert` остались по 512 токенов, хотя окно у неё длиннее.

## Документы

Смешанных документов такой длины в LLMTrace почти нет: у смешанных текстов части detection медиана 639 знаков. Поэтому документы собраны из текстов части classification скриптом [`scripts/long_docs.py`](../scripts/long_docs.py). Тексты одного жанра (статьи, новости, рассказы, отзывы, справочные тексты, ответы на вопросы) склеены через пустую строку, ИИ-куски размечены по знакам. Каждый текст попал только в один документ. ИИ-тексты, которые начинаются с начала человеческого текста, отброшены: генератор продолжал чужой текст, и разметка по знакам для них неверна. Среди текстов `create` таких около трети.

Как читать строки:

- «Человеческий документ: хоть один фрагмент выше порога» — ложная тревога на документе, который целиком написал человек. Именно так выглядит вывод `classify`: «выше порога 1 фрагмент из 12».
- «ИИ-кусок найден» — выше порога хотя бы один фрагмент, в котором ИИ-текста больше половины.
- «Доля ИИ-знаков под отмеченными фрагментами» — сколько ИИ-текста накрыли фрагменты выше порога. «Доля ИИ среди отмеченных знаков» — сколько в них действительно ИИ-текста.
- «По началу» — одна вероятность по первому окну документа, так было до 2.1.0. У `modernbert` первое окно — 8192 токена, в него целиком помещается документ до 20 тысяч знаков и большая часть документа на 40 тысяч.

## Окно 8192: текст целиком или фрагменты

`modernbert` обучена на окне в 8192 токена. Можно было бы и фрагменты резать по 8192, тогда документ почти всегда один фрагмент. Замер той же модели на тех же документах:

| | Фрагменты по 8192 | Фрагменты по 512 |
| --- | --: | --: |
| Фрагментов на документ, медиана | 1 | 12 |
| мс на фрагмент | 1686 | 72 |
| Человеческий документ: хоть один фрагмент выше порога | 0,0 % | 27,0 % |
| Смешанный документ: ИИ-кусок найден | 1,6 % | 92,3 % |
| Документ целиком ИИ: найден | 100,0 % | 100,0 % |

Целиком модель читает текст почти без ошибок: ни одного человеческого документа выше порога и все документы, написанные моделью. Но ИИ-вставку внутри человеческого текста она на таком окне не видит: вставка из одного текста тонет в тысячах слов человека. Поэтому в aiw-ru 2.2.0 у `modernbert` два окна. Вероятность текста в `scan`, `antiplagiat` и `classify` она считает по 8192 токенам (`read_length` в `inference.json`), а `classify` вдобавок режет текст на фрагменты по 512 (`max_length`). aiw-ru до 2.2.0 знает только `max_length` и работает с новой моделью как с прежней, на окне в 512 токенов.

Прежняя `modernbert`, обученная на 512 токенах, на фрагментах по 512 нашла ИИ-кусок в 94,4 % смешанных документов, а хоть один фрагмент выше порога дала в 29,7 % человеческих; новая — 92,3 % и 27,0 %, и считает фрагмент почти вдвое быстрее (72 мс против 126).

## Выводы

Фрагменты находят то, чего не видит начало. В смешанных документах ИИ-кусок нашёлся в 88–92 % случаев против 13–34 % по первому окну. Вставку в конце первое окно в 512 токенов не видит почти никогда (0–1 %), окно `modernbert` в 8192 токена — в 10 % документов. Документ, целиком написанный моделью, все три модели находят всегда.

Цена этого — ложные тревоги на длинном человеческом тексте. У отдельного человеческого фрагмента шанс оказаться выше порога 4–9 %, а фрагментов в документе на 20 тысяч знаков около 11. В итоге хоть один фрагмент выше порога получил каждый четвёртый–третий человеческий документ: 22,5 % у `transformer`, 27,0 % у `modernbert`, 36,9 % у `mini-frida`. По началу документа ложных тревог почти нет, 0–2 %, а `modernbert`, прочитав документ целиком, не ошиблась ни на одном.

Поэтому один фрагмент выше порога в длинном тексте — слабый признак, а не приговор. Два фрагмента и больше встречаются в 8–16 % человеческих документов и в 73–86 % смешанных. Более строгий порог для фрагментов помогает меньше: при 0,98 вместо 0,5 ложные тревоги у `transformer` падают до 11,7 %, у `modernbert` до 10,8 %, а у `mini-frida` почти не меняются (31,5 %), её ошибки на человеческих фрагментах уверенные.

Хуже всего находятся одиночные вставки из одного текста: 69–80 %. Вставка короче фрагмента, и во фрагменте рядом с ней человеческий текст. Из-за того же отмеченные строки шире ИИ-куска: в документах с несколькими вставками ИИ-текст занимает только 42–51 % отмеченного. Фрагмент, где ИИ-текста больше половины, модели отмечают в 66–96 % случаев, где меньше четверти — в 6–21 %.

Перекрытие в четверть окна оставлено. Без перекрытия ИИ находится реже (86,6 % против 89,8 % на valid), перекрытие в половину окна находит чуть больше (92,1 %), но даёт больше ложных тревог (24,8 % против 19,3 %) и почти вдвое дольше.

Из трёх моделей больше всего ИИ-текста находит `modernbert`, меньше всего ложных тревог у `transformer`, он же самый быстрый. У `mini-frida` ложных тревог больше всех.

## Воспроизвести

Нужны части classification test и valid (`scripts/llmtrace.py fetch --split test`, затем `--split valid`) и модели в кэше (`aiw-ru models install modernbert transformer mini-frida`). Прогон новой версии модели рядом со старой: папку новой задаёт переменная окружения модели (`AIW_RU_MODERNBERT_DIR`), а прогону дают свою `--label`.

```bash
uv run --group train --extra ml scripts/long_docs.py build --split test
```

```bash
uv run --group train --extra ml scripts/long_docs.py eval --split test --model transformer
```

```bash
uv run --group train --extra ml scripts/long_docs.py report --overlaps 0 0.25 0.5 --out docs/long-documents.md
```

Для сравнения перекрытий `build` и `eval` запускаются ещё и с `--split valid` и `--overlap 0`, `0.25`, `0.5`.
