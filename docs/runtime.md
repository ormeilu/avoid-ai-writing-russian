# Почему ONNX, а не PyTorch

Модели aiw-ru на машине пользователя работают через onnxruntime. PyTorch нужен только для обучения и экспорта в `scripts/`. Здесь объяснено, почему так, во что это обходится и что сделано, чтобы ONNX не отставал на длинном окне.

## Для кого

Основные пользователи aiw-ru — студенты со старыми ноутбуками, где мало памяти и слабый процессор, и облачные песочницы ИИ-агентов (Claude Code, Codex и подобные). Видеокарты нет ни там, ни там. В песочнице окружение часто ставится заново на каждый запуск через `uvx`, диск и память ограничены. Поэтому главное — сколько качать и сколько памяти занимает проверка, а не рекорд скорости на мощной машине.

## Установка

| | onnxruntime | PyTorch |
| --- | --: | --: |
| Колесо для macOS arm64 | 22 МБ | 127 МБ |
| Установлено на macOS | 79 МБ | 576 МБ, ещё 56 МБ sympy и networkx |
| Колесо для Linux x86_64 из PyPI | 24 МБ | 555 МБ и 1,25 ГБ библиотек CUDA |
| Сборка без CUDA для Linux | та же | 196 МБ, но только из индекса download.pytorch.org |

Размеры колёс взяты из `uv.lock`. Сборку PyTorch без CUDA `pip install` и `uvx` сами не выберут: для этого пользователь должен указать отдельный индекс. На PyTorch код модели к тому же пришлось бы тянуть transformers, это ещё 58 МБ. Для песочницы, которая ставит всё с нуля, разница между 24 МБ и почти двумя гигабайтами решает выбор.

## Скорость и память

ModernBERT (дообученная `modernbert`), один текст, Apple M1. Время — лучшее из нескольких прогонов, память — пик отдельного процесса с загрузкой модели. Замеры шли вперемешку, на машине в это время работал браузер, поэтому точны соотношения, а не абсолютные числа.

8 потоков:

| Токенов | ONNX, как экспортирует transformers | ONNX, FastModernBert | PyTorch |
| --: | --: | --: | --: |
| 512 | 0,13 с, 182 МБ | 0,13 с, 177 МБ | 0,07 с, 500 МБ |
| 2048 | 1,07 с, 781 МБ | 0,47 с, 330 МБ | 0,23 с, 606 МБ |
| 4096 | 3,8 с, 2,5 ГБ | 1,26 с, 540 МБ | 0,55 с, 731 МБ |
| 8192 | 48 с, 3,8 ГБ¹ | 3,2 с, 976 МБ | 1,6 с, 881 МБ |

2 потока, как на слабом ноутбуке или в песочнице:

| Токенов | ONNX, как экспортирует transformers | ONNX, FastModernBert | PyTorch |
| --: | --: | --: | --: |
| 512 | 0,16 с, 182 МБ | 0,13 с, 178 МБ | 0,05 с, 500 МБ |
| 2048 | 1,34 с, 756 МБ | 0,61 с, 330 МБ | 0,27 с, 605 МБ |

¹ Отдельный замер: на 8192 токенах такой экспорт считается слишком долго, чтобы гонять его в общем прогоне.

На M1 PyTorch быстрее быстрого ONNX в 2–2,5 раза. На старом x86-ноутбуке соотношение может быть другим, его никто не мерил. По памяти на окне в 512 токенов, с которым работают все выложенные модели, ONNX втрое легче: 177 МБ против 500. На окне от 4096 токенов PyTorch и быстрый ONNX занимают примерно одинаково.

## Что сделано в ONNX

transformers считает ModernBERT на CPU так, будто все слои глобальные. Два слоя из трёх смотрят только на соседей в окне ±128 токенов, но для них строится полная матрица n × n с маской поверх. Экспорт в ONNX это повторяет, отсюда 48 секунд и 3,8 ГБ на 8192 токенах. `scripts/fast_modernbert.py` меняет три вещи, веса остаются те же:

1. Локальный слой режет текст на блоки по ширине окна, и каждый блок смотрит только на себя и двух соседей. Работа растёт с длиной текста линейно, а не квадратично.
2. Классификатор берёт только токен CLS. Последнему глобальному слою и слоям после него нужны лишь позиции в начале текста, от которых зависит CLS: 257 позиций вместо всех.
3. Глобальные слои считают запросы 16 кусками. onnxruntime держит в памяти оценки одного куска, а не всей матрицы n × n; скорость от этого не падает, а на двух потоках даже растёт.

Логиты совпадают с transformers до 3·10⁻⁶, на 300 текстах valid все метки те же. `scripts/train_transformer.py export` берёт FastModernBert для всех моделей ModernBERT.

## Что пробовали и не взяли

- `com.microsoft.MultiHeadAttention` из onnxruntime вместо внимания глобальных слоёв. Отдельно оператор вдвое быстрее связки MatMul, Add и Softmax, но в целой модели вышло медленнее (2,73 с против 2,48 с на 8192 токенах) из-за лишних перестановок осей, а без кусков память всё равно 2,4 ГБ.
- Оператор `Attention` из ONNX opset 23. onnxruntime требует для него маску размером n × n, от которой мы как раз уходим.
- CoreML в onnxruntime на macOS. Сессия не создаётся: преобразование одного из операторов падает.
- int8 для ModernBERT. На 8192 токенах быстрее примерно вдвое, но выложенная ModernBERT с int8 не прошла допуски по качеству на valid и поставляется в fp32. Веса выбирает `train_transformer.py evaluate` для каждой модели отдельно.

## Итог

onnxruntime остаётся средой выполнения: установка в десятки раз меньше, а по памяти на обычном окне ONNX легче PyTorch. Отставание на длинном окне закрыто экспортом через FastModernBert: по памяти ONNX сравнялся с PyTorch, по времени отстаёт на M1 в 2–2,5 раза, но на окне в 512 токенов, которым пользуются выложенные модели, разница — десятки миллисекунд.

## Воспроизвести

Нужна папка `model/` из запуска `train_transformer.py` с весами PyTorch.

```bash
uv run --group train --group transformer scripts/runtime_bench.py ~/.cache/aiw-ru/llmtrace/transformer/full/rumodernbert-small/model --lengths 512,2048,4096,8192 --threads 8,2 --out docs/runtime.json
```

Числа последнего прогона — в [runtime.json](runtime.json).
